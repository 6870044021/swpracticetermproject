# สคริปต์วิดีโอสอนสร้าง Extra Credits ของ WoTA

วิดีโอยังไม่ได้บันทึก เอกสารนี้เป็นสคริปต์สอนลงมือทำ ไม่ใช่หลักฐานว่ามีวิดีโอแล้ว หลังบันทึกให้อัปโหลดไปยังที่ที่ผู้ตรวจเปิดดูได้ แล้วใส่ URL จริงในสไลด์ Extra Credits และสไลด์ท้าย

## เตรียมก่อนบันทึก

ใช้ฐานข้อมูลทดสอบ MongoDB แบบ replica set หรือ Atlas ที่แยกจากข้อมูลจริง สร้างบัญชี admin ผ่านสคริปต์ในคู่มือ เปิด Swagger, โค้ด และ Postman collection ฉบับใหม่ ปิดหน้าจอที่แสดงรหัสผ่าน, connection string และ token จริง

เริ่มวิดีโอด้วยการอธิบายว่าผู้ชมจะได้สร้างกฎเพิ่ม A1–A13 และทดสอบด้วย Postman แสดงคำสั่งเริ่มระบบและตำแหน่งไฟล์ ให้ผู้ชมทำตามได้ตั้งแต่ต้น

## A1 ถึง A3 รหัสผ่านและคำใบ้

เปิด `coworking/utils/booking.js` อธิบายการตรวจ min8, lowercase, uppercase, digit และขอบเขต bcrypt 72 UTF-8 bytes เปิด `models/User.js` ให้ดูการ hash เฉพาะตอนเปลี่ยน password และไม่ส่ง hash กลับใน JSON

สร้างฟังก์ชันตรวจรหัสผ่านร่วม แล้วนำไปใช้ทั้ง register และ changePassword ใน `controllers/auth.js` สาธิต weak password ได้ 400, strong password สมัครได้ 201, old password ผิดได้ 401, รหัสใหม่ผ่านแล้ว token เก่าใช้ไม่ได้

สร้าง route ตั้งและเรียก password hint อธิบายว่าคำใบ้ห้ามเป็นรหัสผ่านจริง สาธิตตั้งค่า เรียกด้วย email และล้างคำใบ้

## A4 และ A6 ถึง A7 เวลาและการจอง

เพิ่ม `endTime` ใน Reservation และอธิบายรูปแบบ ISO date-time ที่มี timezone ชัดเจน ตัวอย่าง `2030-01-02T10:00:00+07:00` แสดงการแปลงเวลาทำการด้วย Asia/Bangkok

เขียนเงื่อนไข overlap: ช่วงเดิมเริ่มก่อนช่วงใหม่จบ และช่วงเดิมจบหลังช่วงใหม่เริ่ม ช่วง `[10:00,11:00)` กับ `[11:00,12:00)` จึงไม่ทับกัน แสดง query ใน `services/reservations.js` และ transaction ใน `services/bookingTransaction.js` เพื่อให้ตรวจและบันทึกได้อย่างสอดคล้องเมื่อคำขอเข้าพร้อมกัน

เพิ่มการตรวจเวลาเริ่มเดิมก่อนแก้/ลบ เมื่อเหลืออย่างน้อย 1 ชั่วโมงอนุญาต ต่ำกว่า 1 ชั่วโมงปฏิเสธ ตรวจเวลาเริ่มใหม่ด้วยเพื่อไม่ให้เลื่อนข้ามกฎ สาธิต success, overlap409, outside-hours409 และ cutoff409 จาก collection ใช้ unit test อธิบายกรณี 1 ชั่วโมงพอดีให้ไม่ขึ้นกับความหน่วงเครือข่าย

## A5 และ A10 ถึง A13 รีวิว

สร้าง Review ที่อ้างอิง user กับ room เพิ่ม unique index `{user:1,room:1}` และอธิบายว่าการเช็ก findOne อย่างเดียวไม่ป้องกันคำขอพร้อมกัน สาธิตสร้างรีวิวซ้ำแล้วได้ 409 แก้รีวิวเดิม ลบ และสร้างใหม่

แสดง aggregation นับรายการจองที่สิ้นสุดแล้ว ส่งค่า `pastBookings` เพื่อความน่าเชื่อถือ ไม่ใช้จำนวนการจองในอนาคตเป็นประวัติ

เพิ่ม `anonymousReview` เป็น boolean เมื่อตอบกลับต้องลบ user identifier ออกจาก JSON จริง ไม่เพียงซ่อนชื่อบน UI สาธิตเปลี่ยนเป็น anonymous และเปิด response body ให้เห็นว่าไม่มี user ID ใช้ `includeAnonymous=false` เพื่อกรองออก

## A8 โน้ตส่วนตัว

สร้าง Note ที่มี user และ room ใส่เจ้าของจาก JWT ฝั่ง server ทุกครั้ง Query ด้วย `{_id,user:req.user._id}` เพื่อป้องกันการเปลี่ยน ID เพื่ออ่านของผู้อื่น และไม่ populate notes ใน public room catalogue

สาธิตผู้ใช้ A สร้างโน้ต ผู้ใช้ B และ admin อ่านโน้ตของ A ไม่ได้ ส่วน A อ่านและแก้ไขได้

## A9 และ A11 การระงับผู้ใช้

เพิ่ม `userStatus` และ `banUntil` ทำ admin-only suspend route ให้ระงับถาวร ชั่วคราว หรือปลดระงับได้ สร้าง status middleware และตรวจในจุดเขียนข้อมูลที่เกี่ยวข้อง สาธิตผู้ใช้ธรรมดาระงับผู้อื่นได้ 403 ผู้ถูกระงับจองหรือสร้างรีวิวได้ 403 และหลังหมดอายุ/ปลดระงับกลับมาใช้ได้

## จบวิดีโอ

รัน tests และ Postman Runner/Newman แสดงผลจริงจากรอบล่าสุด เปิด `docs/verification.md` และอธิบายขอบเขตหลักฐาน ทิ้งคำสั่งและไฟล์ที่ผู้ชมใช้เริ่มต้นไว้ในคำอธิบายวิดีโอ แล้วใส่ลิงก์ repository ที่มี commit โค้ดตรงกับวิดีโอ
